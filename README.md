# AstrHe

![AstrHe](logo-full.png)

> 氦产生光与热，光热于是便有了构造生命的使命，而生命的使命，便在于孕育灵魂，而每个独特的灵魂，都将以生命为载体，构建独特的光与热。

**AstrHe**（He，氦）是一款 AstrBot 插件，主题是「灵魂」：让 bot 拥有自己的想法——每天零点在后台复盘当天所有聊天，自己想清楚接下来要做什么、为什么做、怎么做，写成规划书和待办，并给自己定好闹钟；白天聊天时带着这份计划；闹钟到点时主动去做。

## 它每天做什么

- **白天**：悄悄记录聊天账本（会话名单内的文字消息、bot 自己的回复与经 `send_message_to_user` 主动发出的消息、戳一戳、贴表情、撤回、进退群，以及不分会话的好友申请），聊天时把属于这个会话的待办和规划段落临时注入请求（不写进对话历史）。
- **主动发出的消息留底**：定时任务唤醒后用 `send_message_to_user` 发出的原文，以及平时聊天里发到别的会话的原文，会补进目标会话的 AstrBot 对话历史，之后聊天或再次被唤醒时都能看到自己说过什么（AstrBot 本身只留一段任务总结）。
- **零点**：补拉聊天历史 → 每个会话派一个只读汇报子代理 → 主 agent 汇总写规划书、待办、闹钟卡片、关系本更新、承诺跟进 → 1 至 2 个审稿子代理复盘 → 一次性提交。**全程无感：夜间不会向任何会话发送任何消息。**
- **首次启用**：插件启动约 2 分钟后会检查当天有没有成功提交过复盘，没有就立即补跑一次。所以第一次打开总开关后，它会马上回看最近 72 小时的聊天，正式写规划书、定闹钟，不必等到零点。
- 某个会话的汇报没写成（模型没给出有效内容）时，主 agent 会被明确告知，自己去翻这个会话的原始记录；审稿意见第一行必须给出「结论：通过 / 需要修改」，没按格式回答的不算审稿，累计 2 次后由主 agent 按清单自查再提交。
- 计划有变化时，夜间主 agent 可以撤销尚未执行的一次性闹钟或仍生效的重复闹钟；改期或改内容通过「取消旧闹钟＋新建」草稿一起审稿、提交，提交时先取消再新建。管理员亲自安排的闹钟，撤销必须附管理员要求取消或改期的消息依据。
- **不同会话用不同人格**：AstrBot 允许按会话（会话管理规则、对话自带的人格、配置文件的默认人格）用不同人格。零点复盘时会查出每个会话白天实际用的人格：和 `persona_id` 不同的会话，由该会话的人格来写汇报；规划与审稿会拿到「会话人格」对照和这些人格的提示词，给这些会话写的段落、待办、闹钟卡片以那个会话的人格为准；规划书里的白天提醒（自我提醒）只注入和 `persona_id` 相同人格的会话。所有会话人格相同时，行为与以前完全一样。
- **到点**：闹钟走 AstrBot 自己的定时任务系统，面板里照常可看、可改、可立即执行。每个闹钟都带着完整的「来龙去脉卡片」。
- **日记**：往日规划书、已了结的待办和承诺长期保存。夜间可搜索、翻阅、补后记、更正或删除，所有修改仍经过草稿、审稿、提交，并留下修订记录。删除进入回收站，30 天内可恢复。

## 设置项

共七个：

| 设置 | 说明 |
|---|---|
| `enabled` | 总开关，默认关闭 |
| `provider_id` | 夜间复盘使用的模型；留空用 AstrBot 当前默认的聊天模型 |
| `persona_id` | 夜间分身共用的人格，从 AstrBot 已有人格中选择；留空或所选人格不存在时回退默认人格。白天用了别的人格的会话，汇报改由该会话的人格来写 |
| `session_whitelist` | 会话白名单：留空沿用 AstrBot 的白名单，填写后以这里为准，见下方「会话名单」 |
| `session_blacklist` | 会话黑名单：AstrBot 没有黑名单，由插件自建，优先级高于白名单 |
| `frontend_landscape` | 横屏打开档案终端时使用的前端：`SOUL OS`（三维版，默认）或 `NORMAL`（MD3 普通版） |
| `frontend_portrait` | 竖屏打开档案终端时使用的前端：`SOUL OS` 或 `NORMAL`（默认） |

## 会话名单（白名单与黑名单）

实时消息会先经过 AstrBot 的白名单，但 AstrHe 夜里补拉历史是直接向 QQ 要的，闹钟到点也是由 AstrBot 定时任务直接唤醒，这两件事都不经过 AstrBot 的消息处理流程，白名单原本管不到。现在插件会按下面的名单自己把关：

- **白名单**
  - 留空：沿用 AstrBot 的白名单。前提是已在 AstrBot「配置文件 → 访问控制 → 白名单」里开启白名单并填写了名单；如果不同会话分配了不同的配置文件，插件按每个会话实际使用的那份判断。AstrBot 没开白名单或名单为空时，不做限制。
  - 填写：以插件这里为准，不再看 AstrBot 的白名单。
- **黑名单**：AstrBot 没有黑名单，由插件自建。写进来的会话一律不碰（管理员亲口要求定闹钟的除外），优先级高于白名单。适合「bot 可以在群里照常聊天，但不想拿这个群来复盘」的情况。
- **AstrBot 会话管理**：在 AstrBot 里整体停用的会话，或单独对该会话停用了 AstrHe 的，插件同样不碰。
- **写法**与 AstrBot 白名单相同：用 `/sid` 获取的会话 ID（如 `default:GroupMessage:123456`），或直接写群号；私聊要写完整会话 ID（如 `default:FriendMessage:123456`）。

对名单外的会话，AstrHe 不会实时记录、夜里补拉或复盘汇报，夜间工具也查不到；不会往里注入待办和规划，不会给它定闹钟，QQ 小工具也不能指定它，或按消息编号读取它的消息原文。

- 管理员的私聊始终会被复盘（除非写进黑名单），免得夜间规划缺了最重要的那份聊天；AstrBot 面板自带的网页对话和 AstrBot 一样不受白名单限制。
- 管理员在名单外的群里和 bot 说话（AstrBot 默认允许），插件不会因此去复盘那个群。
- 管理员亲口要求给名单外的会话定闹钟时照办，但会提醒一句这个会话不在名单里；bot 夜里自己定的闹钟一律不许。
- 目标后来不在名单里的闹钟，会在插件启动（包括修改设置后的重载）和每晚对账时自动取消（包括 bot 夜里自己定的、群友白天在那个会话里定的）；管理员亲口定的保留。
- 名单外以前已经记下的聊天不会立刻删除，只是夜里不再读取，按原有的 30 天规则自然清理。
- 读取 AstrBot 设置失败时会在日志里警告，这时只按插件自己的名单判断。

## 指令（仅管理员）

- `/astrhe run`：立即运行一次夜间复盘并提交（后台执行）
- `/astrhe dryrun`：演练一次，不提交计划（不写规划书、待办、闹钟等，也不清理）；补拉和闹钟对账照常进行，因为它们只是同步已经发生的事实；夜间主 agent 可用的外部工具在演练时同样会被实际调用
- `/astrhe status`：最近一次运行的摘要；运行中显示当前阶段与已用时长
- `/astrhe stop`：停止正在进行的运行（提交前停止判失败，提交后外部动作照常收尾）

## 白天新增的 LLM 工具

`astrhe_todo_update`（勾选待办，备注会回流次夜复盘）、`astrhe_read_plan`（翻规划书：管理员私聊里读全文，其他会话只返回与本会话相关的段落）、`astrhe_schedule`（增强定时工具，替代自带 future_task，支持指定目标会话）、`astrhe_qq_lookup`（QQ 只读查询）、`astrhe_qq_act`（贴表情、戳一戳、点赞、改签名与在线状态，均带频率上限；个性签名所有人可见，白天与夜间复盘共用额度，7 天内最多换一次）。

`astrhe_schedule` 的 `expect_friend_ids` 可由管理员标记预期联系人并当场处理已有申请；重复闹钟仅管理员或夜间主 agent 可创建，相邻至少 1 小时，深夜需约定理由。

## 档案终端（插件页面）

在 AstrBot 面板的插件页面打开「AstrHe 档案终端」查看 AstrHe 的数据。提供两套前端，功能完全对齐：

- **SOUL OS**：三维档案阵列。界面改编自 [RhineLabUI](https://github.com/LBEILC/RhineLabUI)（MIT），去掉了音乐与音效，文字、标志和档案盒模型换成了 AstrHe 的。画面在**打开页面的浏览器**里渲染，需要启用硬件加速；每次打开约下载 16 MB（完整中文可变字体约 12.8 MB、模型约 1.7 MB，其余为页面与解压器），浏览器本地无损解压，保留完整字符和四档字重，不依赖外部字体 CDN。开场动画播放时同步下载模型，下载较慢时开场会停在等待点并显示进度。对显卡有一定要求，低端设备可在设置里开启 SUPER PERFORMANCE 降低画质，或减少、关闭开场动画。
- **NORMAL**：Material Design 3 普通版，基于 [mdui](https://www.mdui.org/)（MIT）。使用系统字体，不下载三维模型和字体，没有重特效，配置较低的电脑和手机也流畅。配色为 MD3 动态配色，亮暗跟随 AstrBot 面板；窗口宽时左列表右详情并排，窄时变成底部导航加全屏详情。

用哪一套由设置里的 `frontend_landscape` / `frontend_portrait` 决定：**只按打开页面那一刻 iframe 的横竖屏选择**（宽高相等算竖屏），选定后转屏或拖动窗口都不会切换（NORMAL 自己的布局仍会随窗口尺寸自适应）。读不到设置时（插件未启用、接口报错或超时）用默认值：横屏 SOUL OS，竖屏 NORMAL。

两套前端的共同功能：

- 五列档案：规划书、待办、闹钟、承诺、关系本，每列显示最近 20 份；**NIGHT RUNS** 查看每晚复盘的运行记录。
- 可以检索档案、导出文本、编辑关系本的关系层（称呼、别名、纪念日）、删除待办或承诺（放入回收站）、取消闹钟。
- 对管理员保密的内容默认打码，点「解密」才显示，只在本次打开期间有效；检索不会命中保密内容。
- AstrBot 插件页面不允许浏览器缓存和存储，所以每次打开都会重新下载页面资源，界面设置也只在本次打开期间有效。AstrBot 所在的机器只提供文件和数据，部署在树莓派等小主机上也没问题；远程访问时速度取决于 AstrBot 主机的上传带宽。
- 前端源码在 `frontend/`（TypeScript + Vite；SOUL OS 用 Three.js，NORMAL 用 mdui），`npm ci && npm run build` 输出到 `pages/dashboard/`（模型先用 meshopt 无损压缩，再与完整字体一起做整文件 Brotli 无损压缩）；插件安装包约 15.4 MB（十进制，低于 16 MB），不含 `frontend/` 下的源码、字体与模型源文件和 `tests/`，仓库完整保留源码及原始资源，修改前端请克隆仓库。发布 ZIP 通过 `.gitattributes` 排除开发文件，前端产物与全部许可仍随包分发；第三方作品与字体许可见 [`frontend/THIRD_PARTY_NOTICES.md`](frontend/THIRD_PARTY_NOTICES.md)。

## 隐私说明

- 插件会在本地保存 **30 天**的文字聊天记录（群聊与私聊），只存在插件自己的数据目录，插件自身不把聊天内容写进日志。注意：AstrBot 运行日志默认会记录每次工具调用的参数和结果，夜间分身翻阅聊天记录时，相关内容也会出现在 AstrBot 的日志里。
- 好友申请记录随聊天账本按 **30 天**保留期清理。
- 每晚复盘开始前（不论当晚成败，演练除外）自动清理满 **30 天**的记录：聊天账本、已结束闹钟及流水、运行与汇报/草稿/审稿、QQ 小动作计数、日记修订和回收站。夜间长期失败时，还没复盘过的消息和闹钟结果会保留到复盘完成；生效中的闹钟、当前运行和最近一次提交的运行保留；关系本与未删除的日记不会自动清理。
- 查看页删除待办或承诺会放进回收站，30 天内可恢复。
- AstrBot 停机错过的一次性闹钟，次夜对账会标为「错过」并删除平台上的残留任务；数据库日志文件（WAL）在每次检查点后收缩到 64 MB 以内。
- 日记删除后不再出现在普通读取、夜间材料或白天注入中；管理员可通过后端接口查看回收站、恢复条目或回退修订。修订记录包含修改前后的内容，满 30 天后清理。
- 夜间复盘会读取这些记录并发送给你配置的模型提供商——**夜间会消耗不少 token**，请留意账单。
- 撤回的消息会被标记并从夜间素材中排除。
- 规划中标记了保密对象的内容，在保密对象在场的会话里会被遮挡。
- 规划书全文里有各个会话的事，白天只在管理员私聊里能翻阅；在群聊和其他私聊里，bot 只能读到与本会话相关的段落。
- 对当前说话人保密（或保密对象在场）的待办和闹钟，在聊天里查不到；非管理员也改不了，回复与编号不存在时相同。管理员报出闹钟编号就能直接修改或取消（列表里仍然看不到，惊喜不会被剧透），也可以在 AstrBot 面板或查看页操作。
- 保密闹钟的面板描述使用中性文字；目标是群聊或保密对象本人的私聊时，总结只写「已完成」。帮手私聊等其他目标会保留实际发送内容和发送结果，便于后续接话；总结不得复述卡片背景、保密对象或禁忌。管理员仍可在 AstrBot 面板查看会话历史；档案终端会给对管理员保密的内容打码，点「解密」才显示。

## 已知限制

- 只支持 **aiocqhttp**（NapCat）平台。
- 适用于 **AstrBot 4.29.0-beta.1 及之后的版本**，不限制安装版本；截至 0.4.0 发布，已对照 4.29.0-beta.1、4.29.0 与 4.29.1 的源码完成测试。
- 如果 AstrBot 配置了 `id_whitelist`，陌生人的好友申请会在 Whitelist 阶段被拦下，插件收不到，自然也无法自动同意。
- 流式回复发出的 bot 消息要等夜间补拉才能进账本；分段插件拆开发送的回复按整条记录，发送时间记为最后一段。
- 补进对话历史的原文与 AstrBot 自己写对话历史一样是「读出整份、改完写回」：如果同一会话恰好同时有别的请求在写，较早的一方可能被覆盖。定时任务唤醒的会话会等 AstrBot 写完任务总结（最多 60 秒）再补。
- 夜间运行不设时长、步数或复盘窗口数据量上限，始终使用流式请求。模型请求失败时保留已完成的对话和工具结果，等待 30 秒重试；连续 3 次失败才终止，中间成功一次就重新计数。模型请求超时与外部工具超时沿用 AstrBot 设置。
- 提交前终止不会应用草稿，白天沿用上一份计划；提交后发生模型错误或人工停止，已提交的计划保留，外部动作照常收尾。可以用 `/astrhe stop` 人工停止。
- 汇报、规划与白天注入的字数只作建议，不做硬截断；每页/每块大小只决定读法，不减少内容。内容较多时会增加 token 消耗。
- 夜间闹钟材料只为生效中的任务展示完整卡片，已结束任务只列最近 7 天（每条一行，含目的和结果），更早的给出条数；历史闹钟、日记搜索和日期列表都支持翻页。未删除的日记长期保存，磁盘占用会随使用增长。
- 管理员撤销依据在代码里核对发送者、发送时间和撤回状态；消息是否明确要求取消或改期，仍由主 agent 和审稿人判断。取消已在执行的重复闹钟会阻止后续触发，当前已开始的执行未必停止。
- 多人格部署时，关系本、承诺和规划书仍只有一份，按 `persona_id` 的人格记录；别的人格的会话只是在规划时按它的人格来写。开启 AstrBot 会话隔离（unique_session）时，夜间复盘按整个群查人格（以群的会话规则和配置文件为准），同一个群里单独给某个人换的人格不会被认出来。
- 重复闹钟在 AstrBot 停机期间错过的触发暂不计入夜间对账，之后的重复照常进行。
- 删除插件数据后重装：闹钟的平台任务存在 AstrBot 里，不会随插件数据一起删除。唤醒时插件会同时核对闹钟编号和平台任务编号，不会把这些旧任务认成新闹钟；首次复盘对账时会自动删除它们。在那之前到点的旧任务仍会照常执行。
- 档案终端 SOUL OS 的开场与三维场景对显卡有一定要求，低端设备可能卡顿，可在设置里降低画质、关闭开场动画，或改用 NORMAL。
- 夜间汇报、审稿与规划都通过 AstrBot 的 agent 运行。如果其他插件全局改写模型回复（例如超过一定字数就压缩成短句的输出长度限制），夜间的汇报和审稿意见也会被改写，导致汇报失败、审稿无效。启用这类功能时，请让它跳过定时任务与插件内部的 agent 运行。

日记管理接口（沿用 AstrBot 面板登录权限，前缀 `/astrbot_plugin_astrhe`）：

- `GET /memory/trash`、`GET /memory/revisions`：每页 50 条，传 `offset` 翻页。
- `POST /memory/restore`：`kind` 为 `plan/todo/promise`，`target` 为规划书日期或条目编号，`reason` 可选。
- `POST /memory/revert`：传 `revision_id`，可附 `reason`；回退也会留下一条新的修订记录。
